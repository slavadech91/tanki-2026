# Протокол

## Соединение ✅
- `https://c6.eu.tankionline.com/config.xml` → `<server address="c6.eu.tankionline.com" version="…"
  wsProtocol="WSS"><webSocketPorts><port>9096</port>` (namespace `alternativaplatform.com/core/config.xsd`).
- Клиент открывает `WebSocket(proto + "://" + host + ":" + port + "/")`, `binaryType = "arraybuffer"`.

## Захват ✅ (`captures/session1.jsonl`, регистрация + обучение + лобби + повторный вход, 2026-10-27)
Сводка: `python -I tools/ws_summary.py captures/session1.jsonl`. Реальный сервер был `c2.eu…:9092`, потом
`c3.eu…:9093` (балансировщик выдаёт разные, в config.xml было c6:9096).

### Рамка
- `u16 BE длина` (без этих 2 байт) + `u16 BE команда` + тело. Пример: `00 2c | 00 02 | …` = 44 байта, команда 2.
- Пинг сервера: `00 01 xx` раз в ~10 с (1 байт тела).

### Начало соединения
1. Первое соединение, клиент → `00 01`-команда 1 «Hash request» (524 байта): открытым текстом список строк
   `resources`, `config-template`, `balancer`, `lang`, … (параметры запуска ❓ разобрать полностью).
2. Сервер → команда 2 «Hash response»: 32 байта хэша сессии + байт-флаг (`… 01`). Затем команда 32 с id `00 00 00 00 05 f6 91 cc` ❓.
3. Команда 32 «ClientLog» от клиента идёт открытым текстом: `screen_show {"screen":"Entrance.SelectEntranceType"}`,
   `button_click {...}` (аналитика экранов).
4. **На каждое «пространство» (space) клиент открывает отдельный WebSocket** и шлёт команду 3 «Open space»:
   `00 2a 00 03 | 32 байта хэша сессии | 8 байт ID пространства` (например `00 00 00 00 05 f6 91 cc`, `… 05 f7 b2 28`,
   `00 00 00 d6 34 b6 93 fb`). Всего за сессию 7 пространств на сервер (вход, лобби, гараж, бой, …).
5. После «Open space» весь трафик соединения зашифрован (оба направления, сквозным потоком через все рамки).

### Шифр ✅ (код прочитан, проверено на захвате: 2469 пакетов, 49 zlib-пакетов распаковались)
Дешифратор: `python -I tools/ws_decode.py captures/session1.jsonl captures/session1.packets.jsonl`,
просмотр: `python -I tools/packets_peek.py captures/session1.packets.jsonl [space] [n]`.
- Ключ (`new ir(hash, spaceId)` @3039696): `e = lo32(spaceId) ^ hi32(spaceId) ^ int32be(hash[0..4]) ^ … ^ int32be(hash[28..32])`,
  `o = b0^b1^b2^b3` (байты `e`). Массивы по 8 байт: сервер→клиент `k[i] = o ^ (i<<3)`, клиент→сервер `m[i] = o ^ (i<<3) ^ 87`.
- Байт (@3058250): `p = c ^ key[idx]; key[idx] = p; idx ^= p & 7` (обратное: `c = p ^ key[idx]; key[idx] = p; idx ^= p & 7`).
- Включается флагом-байтом после хэша в «Hash response» (`01` = шифровать). Управляющие команды (1/2/3/32) не шифруются.

### Пакет ✅ (@1557432, @1548854)
- Заголовок: если `b0 & 0x80` → 4 байта, длина `((b0^0x80)&0x3F)<<24 | b1<<16 | b2<<8 | b3`; иначе 2 байта `(b0&63)<<8 | b1`.
  `b0 & 0x40` = тело сжато zlib. Пакет < 16384 байт пишется 2-байтовым заголовком.
- Тело: карта null-полей (NullMap, @1555485: короткая форма `(r&0x60)>>5` доп. байт на 5/13/21/29 бит;
  длинная `r&0x80`: длина `r&63` байт, при `r&0x40` ещё 2 байта длины), затем **одна или несколько команд подряд**.
  Карта отмечает null у опциональных полей всех команд пакета по порядку.
- Управляющие команды: 1 байт ID + аргументы (`02` + hash[32] + flag, `03` + hash[32] + spaceId[8], `20` + spaceId[8]).
- Команды пространства: `objectId (i64) + methodId (i64) + аргументы`; от сервера перед каждой командой ещё бит
  null-карты (1 = вместо ID байт псевдонима). Полный формат аргументов: [protocol-codecs.md](protocol-codecs.md) ✅.
  Первый пакет сервера в каждом пространстве —
  метод `2ca2091458b7bc93` (по виду: загрузка классов/моделей ❓), клиент отвечает `19368b1c6aca5814` (+ i32 1),
  второй пакет сервера `6a09fce46efe601a` (объекты и их данные ❓).

## ID моделей и методов ✅ (`tools/proto_ids.py` → `server-notes/proto_ids.json`)
- Long-константы в бандле: `new <alias>(lo, hi)` → `id = hi<<32 | lo` (как u32).
- Модель: конструктор `this.<f>=new L(model)`, поля методов, `this.vay()`, `this.<x>=this.<f>` (x57() отдаёт ID модели).
- Входящие методы регистрируются `modelService.l7o(modelId, methodId)` (681 метод, 269 моделей).
- Имя входящего метода: из строки кодека `"_<method>_<arg>Codec"` в `u7j` (есть только у методов с аргументами).
- Имя модели: `vay()` регистрирует класс данных `n7o(this.<f>, r7g(new P(b(<CC>))))`, `toString` CC даёт `"<Name>CC ["` (186 из 269).
  Без CC модель названа по своим входящим методам: `M[method1,method2]`.
- Исходящие методы (363): константы в прокси-классе модели (`new Cmd(obj, this.<f>, buf)`); владелец — модель,
  чей `vay()` создаёт прокси (211 привязано). Имён у исходящих нет (в логе — последние 6 hex-цифр ID).
- Покрытие захвата: 121 из 159 разных ID, 2085 из 2126 пакетов. Остальные — пакеты боя с иной первой командой ❓.
- Служебная модель пространства: `loadDependencies` (2ca2091458b7bc93), ack клиента `19368b1c6aca5814`,
  `loadObjectsData` (6a09fce46efe601a), `unloadObjects` (поле `_unloadObjects_objectsCodec`).

## Кодирование ✅ → [protocol-codecs.md](protocol-codecs.md)
Ниже — первые наблюдения по строкам, оставлены для истории; точный формат и схема — в protocol-codecs.md.
- Свои бинарные кодеки (~480 упоминаний `Codec`), поля описываются как `codec_<поле>`, аргументы методов как
  `_<метод>_<аргумент>Codec`. `@ProtocolOptional`: необязательные поля.
- `CodecNotFoundForCommandException`: «Codec not found for commandId = …»: у команд числовые ID.
- Рядом с сетевым кодом (@3038944) есть XOR-шифрование потока: два массива по 8 ключей, начальный байт из
  хэша/ID (`ClientLog`, `Hash response`, `Open space`, `spaceRegistry`). ❓ разобрать точно.
- Регистрация моделей «spaceRegistry» / «protocol»: объекты разбиты на «space» (пространства).

## Вызов методов ✅ (по коду модели входа, @1076500–1081000)
Прокси `server` модели: каждый аргумент пишется своим кодеком в буфер, затем
`new U(<id модели>, <id метода>, buffer)` уходит в очередь отправки. Входящие: `u7j(methodId, buffer)`,
switch по ID метода, аргументы читаются кодеками (`t7h`). Служебные команды: 1 Hash request, 2 Hash response,
32 ClientLog (см. auth.md).
