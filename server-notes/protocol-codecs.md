# Кодирование данных и аргументов ✅

Всё ниже прочитано в коде и проверено: **2184 из 2184 пакетов пространств** захвата `session1`
(вход, лобби, гараж, чат, обучающий бой, оба направления) декодируются по схеме и собираются обратно
байт в байт (`tools/proto_verify.py`). Клиент принял пакеты, собранные кодеком заново с изменёнными данными

## Примитивы (модуль протокола 24635 @1545519, буфер DataView, big-endian)
| тип | байты | чтение клиента |
|---|---|---|
| Byte | 1, со знаком | `xy`/`p2u` |
| Boolean | 1 (`!= 0`) | кодек `tn` |
| Short | 2 | `u2t`/`q2u` |
| Int | 4 | `v2t`/`r2u` |
| Long | 8 | `w2t`/`s2u` |
| Float | 4 IEEE | `x2t`/`t2u` |
| Double | 8 IEEE | `y2t`/`u2u` |
| String | длина + UTF-8 | кодек `Qt` |
| ByteArray | длина + байты | кодек `Vt` |

**Длина** (`LengthCodecHelper`, @1554070/@1554486): `n < 128` → 1 байт; `n < 16384` → 2 байта `0x8000|n`;
`n < 4194304` → 3 байта `0xC00000|n`. Чтение: `b0 & 0x80 == 0` → `b0`; иначе при `b0 & 0x40` 3 байта, иначе 2.

## Null-карта и optional (@1554635 запись, @1555479 чтение, @1551264 декоратор)
- Одна карта битов на весь пакет, перед командами. Биты MSB-first. Каждое optional-значение берёт следующий бит:
  1 = null (значения нет), 0 = значение идёт дальше.
- Запись по числу битов `w`: `w ≤ 5` → 1 байт `b0>>>3`; `≤ 13` → 2 байта, первый `(b0>>>3)+0x20`, дальше
  `(b[k+1]>>>3)+(b[k]<<5)`; `≤ 21` → 3 байта (`+0x40`); `≤ 29` → 4 байта (`+0x60`);
  `≤ 504` → байт `0x80+N` и `N=ceil(w/8)` байт; иначе 3 байта `0xC00000+N` и `N` байт.
- Чтение короткой формы даёт ровно 5/13/21/29 битов (хвост нулевой).

## Составные типы
- List / Set / Array: длина (LengthCodecHelper) + элементы. Map: длина + пары ключ, значение.
- Enum: Int-код, по коду `switch` выбирает элемент; запись пишет `ordinal`. Коды и имена — в схеме.
- Структура (сгенерированный кодек): поля подряд в порядке чтения кодека (`t7h`), без длины и тегов.
  Optional-поле — бит null-карты перед значением; non-optional примитивы часто читаются «встроенно».
- Регистрация кодеков: `protocol.p7g(CodecInfo, codec)` и `q7g(KClass, codec)` (= `map.put`, поздняя
  регистрация заменяет раннюю; ручные кодеки ставятся после сгенерированных). CodecInfo: `TypeCodecInfo(e)`,
  `EnumCodecInfo(b)`, `ListCodecInfo(c)`, `MapCodecInfo(d)` из экспорта модуля 24635.

## Команды (@3067144 `y7n`, @3067693 `i7q`)
- Сервер → клиент: перед каждой командой бит null-карты. 1 → 1 байт псевдонима (таблица 256 записей
  `(objectId, methodId)`, задаётся `setModelCommandAlias(alias: Byte, objectId: Long, methodId: Long)`),
  0 → `objectId i64` + `methodId i64`. Дальше аргументы метода по схеме.
- Клиент → сервер: `objectId i64` + `methodId i64` + аргументы, бита псевдонима нет.
- В обучающем бою псевдонимы используются ✅ (трафик, сокет 18384.11000): 8 вызовов `setModelCommandAlias`
  и 304 команды через псевдоним. Псевдоним 0 — синхронизация времени `ad6cb1` объекта боя, 3, 5, 6, 7, 9, 11, 13 —
  `updateTurret` (`858f42`) пушек ботов. Кодек обрабатывает их верно (все пакеты собираются байт в байт).
  Во входе, лобби и гараже псевдонимов нет.
- `methodId` глобально уникален: по нему схема знает модель и аргументы (`methods` в схеме).

## Загрузка пространства (модель `0b67d89809bc8a97`)
### loadDependencies(ObjectsDependencies) `2ca2091458b7bc93` (@2350721 `jt`, @2345767 `kt`, @2346141 `qt`)
```
i32 callbackId                        0 → клиент не отвечает; иначе ack 19368b1c6aca5814(i32 callbackId)
i32 nClasses; nClasses × { i64 classId; i32 nModels; nModels × i64 modelId }
i32 nRes; nRes × { i64 id; i16 type; i16 subType; i64 version; u8 isLazy;
                   i8 nDeps; nDeps × i64 (читаются и отбрасываются) }
```
Ресурсы типов 1 и 23 клиент пропускает (`bt`: константы `l85_1 = 1`, `r85_1 = 23` в модуле 71105).
Ack (@2348379): при пустом списке ресурсов — сразу, если `callbackId > 0`; иначе после загрузки не-ленивых
ресурсов. В захвате `callbackId = 0` всегда шёл с пустым списком ресурсов, номер растёт в пределах пространства
(1, 2, …). Классы связывают id класса с набором моделей (`gameTypeRegistry.i7o`).

### loadObjectsData(ObjectsData) `6a09fce46efe601a` (@2350358 `wt`, @2349862 `lt`, @2344957 `ft`, @2348941)
```
i32 nObjects; nObjects × { i64 objectId; i64 classId }     создать объекты (класс должен быть загружен)
i32 nData;    nData × ModelData
ModelData = i64 modelId; если 0 → i64 objectId (дальше идут данные этого объекта)
                         иначе → данные модели кодеком её CC (без длины)
```
Пример (вход): объект `05f691cc` класса `05f69085`, затем `{object 05f691cc}`, `{1d417d595b3e5011: CaptchaCC
{clientKey, stateWithCaptcha:[enum…], useFake}}` и ещё 9 моделей. CC модели: `models[id].cc` в схеме
(регистрация `modelRegistry.n7o(modelId, protocol.r7g(TypeCodecInfo(CC)))` в `vay()` модели).
После данных клиент вызывает у объектов `objectLoaded`.
